- 8080–8085 六个独立进程健康检查通过；默认 H2 文件数据库各自独立，运行数据保留在 `.data/`。
- Nginx `-t` 通过，新前端同步到原 `hmall-nginx`。未自动启动或重载其他 Nginx 进程。

## 12 项真实 HTTP 集成检查

`node tests/integration.cjs` 自动启动 9080–9085 和一个新的测试数据库目录；退出时停止自己启动的进程，不复用演示库。

1. 公开商品目录、网关与业务模块权限、伪造令牌、内部接口保护。
2. 服务端计价、套装与单品需求汇总、五次并发重复下单、重复取消。
3. 组件缺货使整单预留回滚。
4. 十次并发支付与十次并发退款，仅产生一次扣款和一次退款。
5. 余额不足不扣款，订单保持待支付；其他用户不能读取该订单。
6. 退款与发货并发，只能一个分支成功，发货分支可以确认收货。
7. 支付与取消并发，只产生一个最终结果。
8. 强制终止账户服务后，持久化支付操作可恢复，余额只扣一次。
9. 扣款后强制终止商品服务，通知重试和订单恢复最终完成，不重复扣款。
10. 库存为 2 时八次并发下单，恰好两单成功，取消后库存恢复。
11. 测试有效期设为 8 秒，自动超时关闭，库存只恢复一次；正式配置为 900 秒。
12. 修改商品不改变订单快照，后台统计来自订单，通知最终得到确认。

最终结果：`ALL 12 INTEGRATION CHECKS PASSED`。原始机器可读结果在 `test-results/integration.json`，该目录不提交 Git。

## 浏览器检查

`node tests/browser.cjs` 使用本机 Edge 无界面运行，真实操作两端：登录、套装加入购物车、确认收货地址、下单、演示余额支付、退款、后台登录、真实统计、管理员发货、用户收货、套装编辑。还验证了筛选切换、390px 手机宽度无横向溢出、移动导航可用以及无 JavaScript 页面错误。

最终结果：`BROWSER FLOW PASSED`。截图已检查，位于 `docs/screenshots/`：用户首页、用户订单、管理概览、商品管理和手机首页。浏览器操作产生的订单属于本机演示数据，统计与余额随之变化。

## 修复的故障恢复问题

故障注入在修复前两次复现：交易库保存了 PAYING，商品服务重启后对应预留记录丢失。原因是本地 H2 默认允许提交与日志刷盘之间存在延迟。各模块和测试库加入 `WRITE_DELAY=0` 后，单独场景通过，再运行全部 12 项检查通过。没有通过放宽预期状态或等待库存损失来规避该失败。

## 未运行验证的环境

当前机器没有可用 Docker，也没有运行的 Nacos/RabbitMQ。本次验证覆盖本机 H2 + HTTP 通知的实际业务流程，以及中间件配置的 Java 构建。MySQL、Docker Compose、Nacos 注册和 RabbitMQ 发布/消费的真实运行需要具备对应环境后验证；附带配置不代表这些服务已部署。没有接入真实微信/支付宝，也没有进行生产吞吐量或多副本压测。
